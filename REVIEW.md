# REVIEW.md

Review of the starter `app/main.py` (the first commit in this repository). Line numbers refer to that starter file.
Examples assume a 09:30 - 18:30 shift unless stated otherwise; times are IST.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | module, L22-23 | Connection details are hard-coded as fallbacks (`mongodb://localhost:27017`, `attendance_db`), so a missing variable silently points the app at the wrong database. | Start the app without `MONGO_URI`: it starts and talks to a local database instead of failing. | `required_env()` reads `MONGO_URI` / `MONGO_DB` and fails fast at startup if either is missing. |
| 2 | module, L22 | `MongoClient` is created without `tz_aware=True`, so every datetime read back is naive and its time zone is a guess. | `punch_in.astimezone(IST)` on a value read from MongoDB is interpreted as server-local time, shifting it. | `MongoClient(..., tz_aware=True)`; every instant in the code is an aware UTC datetime. |
| 3 | whole file | No indexes are created, so nothing enforces "one employee per `emp_code`" or "one record per (`emp_code`, `date`)", and every list/analytics query is a collection scan. | `/admin/explain` would show `COLLSCAN`; two parallel creates both succeed. | Indexes are created idempotently in the FastAPI `lifespan` hook (see DECISIONS.md). |
| 4 | `health`, L72-74 | Always returns 200; it never talks to MongoDB, so it cannot return 503. | Stop MongoDB: `/health` still says `ok`. | `ping` the server; `ConnectionFailure` -> 503. |
| 5 | `compute_late_minutes`, L35 | Builds the shift start with `replace(hour, minute)` on whatever zone `punch_in` is in (naive server-local from L102), not IST. | On a UTC server, a punch at 09:40:01 IST is 04:10:01, compared with "09:30" UTC, so late = 0. | Convert to IST and build the shift start with `datetime.combine(day, shift_start, tzinfo=IST)` (`shift_window`). |
| 6 | `compute_late_minutes`, L36-37 | Truncates to whole minutes *before* the grace check, so `minutes > 10` misses everything between 10:01 and 10:59 after shift start (R2 says strictly more than 10:00). | 09:40:01 -> 0, expected 10. 09:40:59 -> 0, expected 10. | Compare elapsed **seconds** with 600, then floor to minutes. |
| 7 | `compute_late_minutes`, L35 | Overnight shifts: the shift start is taken on the punch's calendar day, so an after-midnight punch looks early. | Shift 22:00-06:00, punch 00:30: returns 0, expected 150. | Compute against the attendance date from R1 (`attendance_date`) and `shift_window`. |
| 8 | `compute_work_hours`, L41 | `round()` on a float is neither half-up nor exact (banker's rounding plus binary error), and instants are not truncated to seconds first (R1, R4). | 450 s -> `round(0.125, 2)` = 0.12, expected 0.13. 9630 s -> 2.67, expected 2.68. 09:00:00.999 -> 09:07:30.001 gives 0.12, expected 0.13. | Whole-second instants, then `Decimal(seconds) / 3600` quantized with `ROUND_HALF_UP` (`round_half_up`). |
| 9 | `compute_overtime`, L47 | No 30-minute minimum (R3). | Punch-out 18:35 gives 5, expected 0. | Overtime is kept only when the floored minutes are >= 30. |
| 10 | `compute_overtime`, L46 | The shift end is always on `date_str`; for an overnight shift it is the next day. | 22:00-06:00 shift, out 06:40 next day: returns 1480 minutes, expected 40. | `shift_window` moves the end to the next day when `shift_end <= shift_start`. |
| 11 | `compute_overtime`, L47 | Subtracts a naive `punch_out` (as stored by L102) from an aware `end`. | `TypeError: can't subtract offset-naive and offset-aware datetimes` -> 500. | All instants are aware UTC. |
| 12 | `EmployeeIn`, L53-60 | No validation: any `emp_code`, email, shift time or date is accepted; `shift_start == shift_end` is accepted. | `{"emp_code": "x", "shift_start": "25:99", "joined_on": "2026-02-30"}` -> 201, expected 422. | Pattern / length constraints from the contract, a real calendar-date check and a model validator for equal shift times. |
| 13 | `PunchInIn`, L64-66 | `punched_at: int` in lax mode accepts `"1783311001000"`, `1783311001000.0`, `true` and second-based values; `status: str` accepts anything, including `ABSENT`. | `{"punched_at": 1783311001}` (seconds) -> 201 for a date in 1970, expected 422. `{"status": "ABSENT"}` -> 201, expected 422. | `EpochMillis` is a strict int in `[100000000000, 4102444800000]`; `status` is `Literal["PRESENT", "WFH", "ON_DUTY"]`. |
| 14 | `create_employee`, L79-83 | Check-then-insert: two parallel creates both pass the `find_one` and both insert. | 12 parallel POSTs with the same `emp_code` -> several 201s and duplicate employees. | Unique index on `emp_code`; insert and map `DuplicateKeyError` to 409. |
| 15 | `create_employee`, L82 + L85 | `created_at = datetime.now()` is naive local time (stored shifted on a non-UTC server), and it is returned as an ISO string, not epoch milliseconds. | Response has `"created_at": "2026-10-09T..."`; contract says integer ms. | `utc_now()` stored as a BSON date; responses convert with `to_millis`. |
| 16 | `list_employees`, L93 | `skip = page * page_size` skips the first page. | `?page=1` with 3 employees and `page_size=2` returns only the 3rd. | `skip((page - 1) * page_size)`. |
| 17 | `list_employees`, L94 | `total` counts the whole collection, ignoring the department filter (R10). | `?department=Sales` returns 2 items but `total` = all employees. | `count_documents(query)` with the same filter. |
| 18 | `list_employees`, L95 | No sort, so order is insertion order, not `emp_code` ascending; `created_at` leaks out as a datetime. | Insert EMP0003 before EMP0001: EMP0003 is listed first. | `.sort("emp_code", 1)` and `employee_out()`. |
| 19 | `list_employees` / `list_attendance`, signatures | `page` and `page_size` are unvalidated. | `/employees?page_size=0` -> `limit(0)` returns **every** employee; `/employees?page=-1` -> negative skip -> 500; `page_size=1000` is accepted (max is 100). | `Query(ge=1)` and `Query(ge=1, le=100)`, so bad values are 422. |
| 20 | `punch_in`, L101 + L113 | Unknown employee is not checked; `emp["shift_start"]` on `None`. | `{"emp_code": "EMP9999"}` -> `TypeError` -> 500, expected 404. | `get_employee()` raises 404. |
| 21 | `punch_in`, L102-103 | `datetime.fromtimestamp(ms / 1000)` is server-local and keeps milliseconds; the date is the server's calendar date, not IST; the overnight rule (R1) is missing. | On a UTC server, a punch at 01:00 IST is dated the previous day; 00:30 on a 22:00-06:00 shift should be the previous day but the code would use the server date. | `from_millis()` (UTC, truncated to whole seconds) + `attendance_date()` (IST + overnight rule). |
| 22 | `punch_in`, L104-118 | Check-then-insert race: parallel punch-ins for the same day all pass the `find_one`. | 12 parallel identical punch-ins -> several 201s and duplicate records for one day. | Unique index on (`emp_code`, `date`); `DuplicateKeyError` -> 409. Exactly one 201. |
| 23 | `punch_in`, L119-121 | Returns an `id` field (the contract says records have no id) and `punch_in` as a datetime instead of epoch ms. | Response contains `"id": "66f..."` and an ISO `punch_in`. | `record_out()` returns exactly the contract fields. |
| 24 | `list_attendance`, L144-147 | Loads every matching document into memory and sorts/paginates in Python. | With ~100k records, `GET /attendance` reads the whole collection on every call; explain shows `COLLSCAN`. | `find(query).sort(...).skip(...).limit(...)` in MongoDB, backed by indexes; `count_documents` for `total`. |
| 25 | `list_attendance`, L145 | Sorts by `date` only; the contract is `date` desc, then `emp_code` asc. | Two employees on the same day come back in arbitrary order. | Sort `[("date", -1), ("emp_code", 1)]`, matching the `date_-1_emp_code_1` index. |
| 26 | `list_attendance`, L149 | Leaks `id`, returns datetimes, and passes legacy documents through without `half_day` / `history`. | Legacy record (DATA_MODEL sample 9) comes back without `half_day` and `history`. | `record_out()` defaults missing `half_day` to false, `history` to `[]`, `late/overtime` to 0. |
| 27 | `list_attendance`, L126-131 | Dates and status are not validated; `date_from > date_to` is not rejected. | `?date_from=2026-13-45` -> 200; `?date_from=2026-07-15&date_to=2026-07-14` -> 200 with 0 items; `?status=LATE` -> 200. | `DateStr` / `Status` types and an explicit check -> 422. |

## Looked at and decided were fine

- `load_dotenv()` (L20): by default it does **not** override variables that are already set, so real environment variables win as the contract requires. Kept.
- `IST = timezone(timedelta(hours=5, minutes=30))` (L25): correct, India has no DST. Kept.
- Synchronous PyMongo with plain `def` endpoints: FastAPI runs them in a thread pool and `MongoClient` is thread-safe, so parallel requests are fine without Motor. Race safety comes from unique indexes and conditional updates, not from the driver.
- One module-level `MongoClient`: correct; it is a connection pool meant to be shared by the whole process.
- `doc.pop("_id", None)` after `insert_one` (L84, L120): correct, `insert_one` adds `_id` to the dict in place.
- Comparing dates with `$gte` / `$lte` on `YYYY-MM-DD` strings (L139-141): correct, ISO dates sort lexicographically in calendar order, and it keeps the stored format a plain string as DATA_MODEL.md requires.
- `int(...)` truncating toward zero for negative minutes in `compute_late_minutes`: harmless, negative results become 0 anyway.
